# Screen Studio 简体中文补丁 · 兼容性试用包

本包给已有 Screen Studio 的 Mac 用户使用。把本文件和整个文件夹交给有本机文件、终端权限的 AI Agent，即可按 `AGENTS.md` 检查和安装。只会聊天、不能访问本机文件的网页 AI 不能代替你执行安装。

**这不是 Screen Studio 安装包、许可证或官方语言包。当前没有获得官方商业汉化授权，也没有完成独立正版客户的激活、云服务及更新兼容性验证。请勿把它宣传成“所有正版都能装、永久兼容、官方认证”。**

## 本包做什么

- 本地翻译 2,068 条界面文案，覆盖菜单、设置、编辑、录制和导出等界面。
- 从收件人自己的应用中读取资源，再加入翻译层；本包不包含 Screen Studio 软件本体、原始代码包、项目素材或任何人的许可证。
- 安装、翻译均不调用 AI API，不联网上传资料。AI 只负责理解步骤和操作本机；所使用的 AI 服务自身的数据处理规则另行适用。
- 不改激活、试用期限、订阅及付费功能逻辑，也不替代正版购买。
- 附带本地权限检查与可选修复入口。默认只检查应用身份、签名和运行状态，不读取权限数据库、不判断实际授权结果；修复需明确选择与确认，仅撤销本应用所选旧授权，新授权由用户在 macOS 中完成。

## 安装前需要知道

1. 仅支持 macOS，需有 Python 3.9 或更新版本及系统 `codesign`、`ditto`、`lipo` 等工具。无需 Node、npm 或 AI API 密钥。缺少工具时由 Agent 说明并通过官方来源安装，不能假装已完成。
2. 保存工作并退出待汉化的 Screen Studio。安装会保留完整备份，另做临时副本；请预留数 GB 磁盘空间，以检查结果为准。
3. 修改应用资源会使原开发者签名失效，本包改用本机临时签名。它不等于恢复官方签名或重新公证。旧权限记录可能仍绑定原签名，**即使系统设置中的录屏、辅助功能开关显示已开启，应用仍可能不认可**。2026-11-08 本机已复现该问题，重新授权后已通过首次权限页，并完成实际屏幕录制、停止和播放测试；本次录屏导出未做。也可能遇到麦克风重新授权、系统启动拦截、登录/钥匙串或更新兼容问题。
4. 安装器不会自动重置或授予权限，不会关闭 Gatekeeper、SIP、证书验证，不删除 quarantine，不修改 hosts 或系统授权数据库。签名导致的旧权限问题可按下文单独诊断并由用户重新授权；系统安全策略或企业管理限制无法正常解决时，停止并恢复原版。

## 命令入口

在这个文件夹里执行。路径有空格时保留双引号。

```sh
python3 installer.py preflight --app "/Applications/Screen Studio.app"
```

检查通过且理解上述影响后：

```sh
python3 installer.py install --app "/Applications/Screen Studio.app" --accept-signature-change
```

安装器输出 JSON，包含本次备份和状态文件路径。保存这个 `state.json`。后续按实际路径执行：

```sh
python3 installer.py verify --state "/实际备份目录/state.json"
python3 installer.py restore --state "/实际备份目录/state.json"
```

若应用不在默认 `/Applications/Screen Studio.app`，验证和恢复命令也必须追加同一个 `--app "实际应用路径"`。

恢复前同样先保存工作并退出应用。备份位于用户电脑，不在这个分发包里。若应用已被更新或另行修改，恢复器会拒绝用旧备份直接覆盖；请让 Agent 先核查并保留新版本。

## 已开启权限却仍卡住时

本机案例的系统日志明确显示旧的应用代码签名要求不匹配。下面是该案例已使用的恢复流程，不保证能解决所有权限故障，也不是每次安装都要执行的步骤。

1. 确认正在打开安装后的同一份 Screen Studio，保存工作并彻底退出。先说明：重置会撤销本应用对应的已有授权，需要用户重新确认；只有用户同意这次重新授权时才继续，安装流程不得自动执行。
2. 可双击本包的“检查与修复权限.command”：先只读检查，直接回车即退出；只有选择要处理的服务并完整输入 `REPAIR` 后才尝试撤销旧授权。也可让 Agent 使用以下入口，默认检查与修复必须分开：

   ```sh
   python3 repair_permissions.py --help
   python3 repair_permissions.py --check
   python3 repair_permissions.py --dry-run --services ScreenCapture Accessibility
   # 只有用户已同意本次重新授权，且应用已退出时执行：
   python3 repair_permissions.py --repair --confirm --services ScreenCapture Accessibility
   ```

   非默认应用路径追加 `--app "实际应用路径"`。工具固定限制 bundle ID 为 `com.timpler.screenstudio`，仅支持本包验证版本；未知服务、未确认修复、签名无效或目标应用仍运行时拒绝重置。底层仅执行 `/usr/bin/tccutil reset 指定服务 com.timpler.screenstudio`，不执行全局重置。

   麦克风或摄像头也出现权限故障、且你需要使用时，才分别使用 `--services Microphone` 或 `--services Camera`。它们不会被默认捆绑处理；不要为纯屏幕录制授予不需要的权限。

3. 打开“系统设置 → 隐私与安全性”，分别在“屏幕录制”（部分系统名为“屏幕与系统音频录制”）和“辅助功能”中，重新添加实际使用的应用，例如 `/Applications/Screen Studio.app`，并开启权限。麦克风/摄像头则重新打开应用并使用相应功能触发系统授权。Touch ID 或密码验证由用户本人在系统界面完成，不交给 Agent 或补丁作者。
4. 按 macOS 提示退出并重新打开应用，检查能否进入“开始录制”界面。随后用无隐私内容实际录制几秒，停止、预览并本地导出，确认结果能打开。

**截至本记录，开发电脑已完成用户系统验证、屏幕录制及辅助功能重新授权，已进入中文“开始录制”界面；约 65 秒真实屏幕录制、停止、编辑器画面预览、播放及暂停已通过。麦克风也已单独重新授权，系统日志为允许，界面警告消失。测试时关闭麦克风与摄像头，实际声音、摄像头录制未测试，本次录屏的导出未执行。** 此前导入已有视频的导出测试单独通过，不能与本次录屏拼成已经完成的全流程验收。测试素材不随包提供。

`tccutil reset` 只撤销旧授权，不会自动放行。不要省略 bundle ID、使用 `reset All`、直接编辑权限数据库或关闭系统保护。命令失败、企业管理限制或正常重新授权后仍不兼容时，停止并保留诊断信息，按安装回执恢复原版。以后重新签名或恢复原版也应重新检查权限，不预设旧授权仍然有效。

## 使用和更新

安装后要检查菜单、设置、编辑器、导出窗口。导入已有视频后的预览/导出，与实际屏幕录制是两项独立验收：还需用无隐私内容完成从屏幕开始录制、停止、预览及本地导出的短测试；未完成任何一步都应标为“未验证”。注册码、密码、系统权限、购买条款由用户按真实情况处理；不要把这些内容提供给补丁作者。

官方更新可能覆盖补丁，也可能改变资源结构。**不得直接给新版本套用本包，不得关闭安全更新来维持汉化。** 如需更新，先恢复官方版本再按官方流程升级，新版本需单独适配。

字典覆盖范围不等于每一条远程通知、云端错误和未来页面都已实机验证。品牌名和编码格式保留原名；补丁不修改用户文件或内容数据，已对已知编辑区域、项目名和字幕区域作保护。所有自定义文字在各个显示位置是否都不会误译，尚未穷尽验证。

详见 `AGENTS.md`（AI 安装流程）、`验证记录.md`（证据与边界）、`销售前必读.md`（商业使用状态）。
